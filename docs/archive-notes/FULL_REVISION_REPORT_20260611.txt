Executive summary
- Fixed the admin-creation blocker by restoring a complete browser API helper (CV_API.request) and preserving legacy token keys used by the admin panel.
- Preserved server-side security: only authenticated Super Admin users can create Admin or Super Admin users.
- Added mobile/tablet CSS hardening for admin pages, forms, tabs, tables, cards, modals, navigation and overflow.
- Added cache-busting for the admin API/client scripts and ensured favicon is linked.

Root cause of admin creation issue
- apiClient.js exposed CV_API but did not implement CV_API.request(), while admin.js called CV_API.request('/admin-users', ...).
- Multiple legacy admin scripts used different token names; the fixed helper now reads/writes all required legacy token keys without bypassing backend authorization.
- The server route /api/admin-users already required superAdminOnly; the issue was frontend/API helper mismatch, not the database route.

Root cause of mobile issues
- Admin layouts used multi-column grids and large tables without sufficient small-screen overrides.
- Navigation and tab controls could overflow on 320-414px widths.
- Forms, tables, sticky save controls, modals and dashboards needed mobile-specific wrapping, scrolling, and touch target improvements.

Detailed fixes made
- Added CV_API.request(path, options) with /api path normalization, JSON/FormData handling, no-store cache, credentials same-origin, Bearer token injection, safe response parsing and clear error propagation.
- Added CV_API.available(), token(), currentAdmin(), adminLogin(), refreshAdmin(), customerLogin(), customerRegister(), forgotPassword(), logout(), and createOrderFromPrototype() in a consistent helper.
- Preserved legacy token compatibility: cvAdminApiToken, adminToken, token, authToken, cvAdminSession, adminSession.
- Exposed the helper as both window.CV_API and global CV_API for older admin scripts.
- Updated admin script cache versions in admin.html and public/admin.html.
- Added favicon link to admin HTML.
- Added responsive CSS hardening for mobile widths 320px, 375px, 390px, 414px and tablet widths.
- Prevented accidental horizontal overflow on admin/public pages.
- Improved mobile touch targets, form sizing, modal layout, admin tabs, navigation scrolling and table overflow handling.

Security and environment safeguards preserved
- Admin creation remains protected by the server-side superAdminOnly middleware.
- Normal admins cannot create or promote admin accounts.
- Duplicate admin emails are still rejected by the backend.
- Passwords are still hashed server-side with bcrypt.
- No secrets were hardcoded.
- JWT_SECRET, DATABASE_URL, NODE_ENV and ALLOWED_ORIGINS remain environment-driven.
- Backend validation and permission checks were not weakened.
