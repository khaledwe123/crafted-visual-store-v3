Executive summary

Root cause
- apiClient.js exposed CV_API but did not define request(), while admin.js expected CV_API.request().
- Several overlapping patch files created competing admin create handlers. The final stable patch overrides them safely and calls /api/admin-users directly with the authenticated Super Admin token.

Security preserved
- Admin creation still requires Super Admin backend authorization.
- Passwords are sent to backend and hashed by bcrypt.
- Duplicate admin emails return conflict.
- System owner cannot be deleted.
- Current user cannot delete themselves.

Commands/checks run
